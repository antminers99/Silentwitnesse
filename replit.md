# Silent Witness

## Overview

Silent Witness is a privacy-first evidence fingerprinting tool. It allows users to create cryptographic fingerprints (SHA-256 hashes) for files, videos, audio, documents, and written testimony — entirely in the browser, without ever uploading original files to any server.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **Frontend**: React + Vite + Tailwind CSS (artifacts/silent-witness)
- **API framework**: Express 5 (artifacts/api-server)
- **Database**: PostgreSQL + Drizzle ORM
- **Validation**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (from OpenAPI spec)
- **Build**: esbuild (CJS bundle)
- **Crypto**: Web Crypto API (SHA-256, browser-side only)
- **EXIF reading**: `exifr` (browser-side, no upload)

## Threat Model

**What Silent Witness does NOT prove:**
- That an event happened
- The identity of a perpetrator
- The truth or accuracy of any content
- Legal admissibility in any jurisdiction

**What it may help show:**
Silent Witness may help show that a matching file, text, or evidence package existed before a recorded time. It does not prove that an event happened, identify a perpetrator, or guarantee legal admissibility.

**Per-field trust levels:**
- `createdAtLocal` — generated by the user's browser at fingerprint creation time. Comes from the device clock. **Not independently verified.** Can be set to any value by the user.
- `serverReceivedAtUtc` — set exclusively by the server when the POST /api/records request is received. **The frontend cannot set or override this field.** Proves only that the registry received the fingerprint by that time.
- `packageHash` — SHA-256 of the manifest JSON (without the packageHash field itself). Deterministic; any change to the manifest invalidates it.

**What is NEVER stored:**
- Original files (images, videos, audio, documents)
- Raw filenames (only SHA-256 of filename is stored)
- GPS coordinates
- Exact locations (street level)
- Victim/witness/suspect names
- Phone numbers
- Any personally identifying information
- Email addresses

**What IS stored (only if user explicitly submits):**
- SHA-256 fingerprint (package hash)
- Event type (kidnapping, detention, etc.)
- Evidence type (video, image, etc.)
- Country / region / city (broad location only, user-provided)
- Safe descriptor metadata (file size bucket, duration bucket, GPS presence flag — not coordinates)
- createdAtLocal (browser clock, unverified)
- serverReceivedAtUtc (server clock, authoritative)
- Quality level (A/B/C)

**Key limitations:**
- A deleted original cannot be recovered from a hash
- Public notes must not include names, exact locations, phone numbers, vehicle plates, or accusations
- No maps, GPS, street-level data, or exact coordinates in this version
- Quality D records are rejected from the public registry (can be saved locally)
- No blockchain anchoring in this MVP

**No precise mapping:**
No maps, GPS, street-level data, or exact coordinates are accepted or stored. Only country/region/city fields are allowed, and all are user-provided manually.

**Future anchoring note:**
Future versions may anchor daily Merkle roots to OpenTimestamps or public chains. This MVP does not perform blockchain anchoring.

## Privacy Model

**Request size limits:**
- JSON body limit: 100 kb
- The backend does not accept file uploads, base64 evidence, or multipart form data

**Server logging:**
- The server logs only: request method, URL path (without query string), HTTP status code, package hash, and quality level on submission
- Request bodies, public notes, and metadata are never logged

## Architecture

```

lib/
  api-spec/          — OpenAPI spec + orval codegen config

```

## Pages

- `/` — Home: explanation of how the tool works, primary action buttons
- `/create` — Create Witness Record: 3-step flow (type selection → safe context → generate record)
- `/verify` — Verify Evidence: compare local file hash against published fingerprint or manifest JSON; registry lookup by hash
- `/records` — Public Registry: table of submitted public fingerprints with filters and hash search
- `/records/:packageHash` — Record Detail: both timestamps with explanations and legal wording
- `/protocol` — Protocol paper: full explanation of what the tool does and does not prove
- `/safety` — Safety guide: field-safety advice for witnesses and journalists

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)

## API Endpoints

- `GET /api/healthz` — health check
- `GET /api/records` — list public records (filterable by country, region, eventType, etc.)
- `POST /api/records` — submit a new public fingerprint (safe metadata only; 100 kb body limit; Quality D rejected)
- `GET /api/records/stats` — aggregate stats for the registry
- `GET /api/records/:packageHash` — fetch a specific record by hash

## Record Status Vocabulary

| Status | Meaning |
|---|---|
| `timestamped_only_not_verified` | Default for all MVP submissions. Registry received the fingerprint; no external review. |
| `exact_match_published` | A verified partner confirmed an original file matches this fingerprint. |
| `not_matching` | A presented file does not match the fingerprint. |
| `externally_reviewed` | A trusted organisation has reviewed and annotated the record. |

All records submitted via the public form default to `timestamped_only_not_verified`.

## Safety & Spam Controls

- Honeypot field on submission form (blocks simple bots)
- Rate limiting: 10 submissions per IP per hour
- Server-side validation: rejects phone numbers, GPS coords, violent language in public notes
- Duplicate hash detection: returns `already_registered` with link to existing record (409)
- Quality D records rejected from public registry with clear message
- JSON body capped at 100 kb

## Database Tables

- `witness_records` — public fingerprint records
- `rate_limit` — IP-based rate limiting (in-memory for MVP)

## Demo Records

Three demo records are seeded, clearly marked with `is_demo: true` and public warnings reading "DEMO RECORD — NOT REAL." They cannot be mistaken for real records.

## Not Planned for MVP

- Email collection or notifications (privacy-sensitive; not planned)
- Blockchain anchoring (future note only)
- Maps or geographic visualisations
- Exact GPS or street-level coordinates
