Core product rule:
Silent Witness does NOT publish original evidence files. It only creates and stores fingerprints, safe descriptors, and public metadata. The original file must stay on the user’s device.

Critical additions required:

2. Add admin/reviewer approval dashboard.

==================================================
1. PUBLIC SUBMISSION STATES
==================================================

Every submitted public record must have a publication status.

Use these statuses:

- local_only
  Means the user generated a proof package locally and did not submit it.

- submitted
  Means the public fingerprint was submitted to the server but is not visible publicly yet.

- pending_review
  Means the record needs reviewer approval before appearing publicly.

- public_timestamped_record
  Means the record passed safety checks and is visible in the public registry.

- rejected_for_public_registry
  Means the record is not allowed in the public registry.

- retracted_by_holder
  Means the holder used a retraction token to hide the public record later.

- exact_match_published
  Means a later published file was checked and exactly matched a stored hash.

Default for new server submissions:
submitted or pending_review, not public_timestamped_record.

No record should appear in the public registry until it is approved automatically by strict rules or manually by a reviewer.

==================================================

A. File evidence
B. Written testimony
C. Evidence package

For selected files:
- Calculate SHA-256 locally in browser.
- Do not upload original files.
- Show banner:
  “Processing locally. Your file is not uploaded.”

For every file:
- Store individual SHA-256 in local manifest.
- Create packageHash from canonical manifest JSON.
- Do not publish raw filename.

For images/videos:
Store only confirmed safe descriptors.

Allowed safe descriptor fields:

- exact GPS
- device model
- manufacturer
- serial number

- IP address

- device fingerprint

If a value cannot be extracted confidently, omit the field entirely.

4. ORIGINAL HASH, SAFE COPY HASH, AND COMPRESSION PROBLEM
==================================================

The app must clearly explain:

Exact SHA-256 matches only work if the later file is byte-for-byte identical.

If a video/photo is sent through WhatsApp, Telegram, Facebook, YouTube, or other platforms, it may be compressed or re-encoded, so its SHA-256 may change.

Implement fields in manifest:

- originalHash
  SHA-256 of the original selected file.

- safeCopyHash
  Optional. For MVP this can be null unless a safe export feature exists.

- mediaFingerprint
  Optional placeholder for future perceptual/media fingerprinting.
  Do not claim this works until implemented.

On the Verify page:
- Exact match = strong cryptographic match.
- No exact match = not necessarily fake; it may have been compressed or modified.
- If no exact match, display:
  “This file does not exactly match the stored hash. It may be a different file, or it may have been compressed/exported by another platform. Exact verification requires the original file or the exact safe copy.”

Do not claim similarity matching unless it is actually implemented.

5. PUBLIC SAFETY CHECKS BEFORE SUBMISSION
==================================================

Before a record can be submitted publicly:

Reject or force private/local-only if public fields contain:
- phone numbers
- GPS coordinates
- street addresses
- exact locations
- names of victims/witnesses/suspects
- vehicle plates
- direct accusations
- sectarian slurs
- incitement
- revenge language
- “go kill”
- “all of them are guilty”
- dehumanizing group language

Public note:
- Keep max length 200 characters.
- It is optional.
- Prefer replacing unsafe notes with:
  “Details withheld for safety.”

Quality rules:
A = evidence package with file hash + safe descriptor + event type
B = file evidence + safe descriptor
C = organized written testimony only
D = low value / unsafe / empty / abusive / spam

Do not allow Quality D into public registry.
Quality D may be downloaded locally as proof package only.

10. RETRACTION TOKEN
==================================================

When a user creates a public record locally, generate a retraction token.

The proof package includes:
- retractionToken raw secret
- packageHash
- manifest

The server stores only:
hash(retractionToken)

Add route:
/retract

User pastes packageHash + retractionToken.
Backend hashes token and compares.
If valid:
publication_status = retracted_by_holder
retracted_at_utc = server UTC time

The public registry should no longer show retracted records.
Record detail may show:
“Retracted by holder”
but not public metadata if safety requires hiding.
