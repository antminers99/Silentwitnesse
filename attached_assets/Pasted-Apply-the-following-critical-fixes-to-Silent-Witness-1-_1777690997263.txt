Apply the following critical fixes to Silent Witness.

1. Replace any wording that says or implies “legal proof” or “legally sufficient”.
Use this safer wording:
“Silent Witness may help show that a matching file, text, or evidence package existed before a recorded time. It does not prove that an event happened, identify a perpetrator, or guarantee legal admissibility.”

2. On every record detail page, show a clear legal/safety warning:
“This record is a timestamped fingerprint only. It is not public proof that the event happened. Verification requires the original file or text to match the stored fingerprint.”

3. Duplicate package hash behavior:
If POST /api/records receives an existing packageHash, do not create a duplicate and do not fail harshly.
Return HTTP 200 or 409 with a structured response:
{
  "status": "already_registered",
  "recordUrl": "/records/{packageHash}",
  "serverReceivedAtUtc": "..."
}

4. Add hash search:
On /verify and /records, allow the user to paste a SHA-256/packageHash and search the registry.
If found, show the record detail link.
If not found, show:
“No public registry record was found for this fingerprint.”

5. Do not accept Quality D public submissions.
Quality D records may be generated locally and downloaded as proof packages, but POST /api/records must reject them with a clear message:
“Low-quality records can be saved locally but are not accepted into the public registry.”

6. Remove or downgrade blockchain anchoring from “high priority”.
Add it only as a future note:
“Future versions may anchor daily Merkle roots to OpenTimestamps or public chains. This MVP does not perform blockchain anchoring.”

7. Remove email notification from roadmap or mark it as privacy-sensitive and not planned for MVP.
Do not add email collection.

8. Add a privacy-safe logging rule:
The Express server must not log request bodies, public notes, or metadata that may contain sensitive content.
Only log minimal operational events.

9. Add request size limits:
Set JSON body limit to a small safe value, for example 100kb.
Reject anything larger.
The backend must never accept file uploads, base64 evidence, or multipart evidence.

10. Update README with a “Threat Model” section:
- Original evidence never leaves the browser.
- Server stores only public metadata and hashes.
- createdAtLocal comes from the user device and is not independently trusted.
- serverReceivedAtUtc is created by the server and means only that the registry received the fingerprint by that time.
- The system does not prove truth, guilt, or legal admissibility.
- A deleted original cannot be recovered from a hash.
- Public notes must not include names, exact locations, phone numbers, vehicle plates, or accusations.

11. Add a “No precise map in MVP” note:
No maps, GPS, street-level data, or exact coordinates in this version.
Only country/region/city fields are allowed, and all are user-provided manually.

12. On the Create page, before public submission, show a final confirmation:
“You are about to submit only the fingerprint and safe public metadata. The original evidence file will not be uploaded. Do not include names, exact locations, or accusations in public notes.”

13. Add a record status vocabulary:
- timestamped_only_not_verified
- exact_match_published
- not_matching
- externally_reviewed
For MVP, default all submitted records to timestamped_only_not_verified.

14. Ensure createdAtLocal and serverReceivedAtUtc remain separate:
- createdAtLocal is generated in browser.
- serverReceivedAtUtc is generated only on backend.
- Frontend cannot set or override serverReceivedAtUtc.
- Display both with explanation.

Keep design simple, serious, and minimal.
No hype.
No AI branding.
No claims of legal certification.
