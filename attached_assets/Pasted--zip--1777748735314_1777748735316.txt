أهم المشاكل التي يجب إصلاحها أولاً
1. خلل خطير في تحقق الـ manifest
في create.tsx يتم حساب packageHash قبل إضافة retractionToken.
لكن في verify.tsx عند إعادة حساب hash، يتم حذف packageHash فقط، ولا يتم حذف retractionToken.
النتيجة:
الـ manifest الذي ينزّله المستخدم قد يظهر لاحقاً أنه “tampered” حتى لو لم يتغير.
الإصلاح: إما:
TypeScript
const { packageHash, retractionToken, ...rest } = manifest;
return sha256(JSON.stringify(rest, null, 2));
أو الأفضل:
افصل الملفين:
public-manifest.json
private-retraction-token.txt
هذا أنظف وأقوى قانونياً.
2. “Public Note” لا يتم نشره فعلياً
في الواجهة يوجد حقل اسمه Public Note.
لكن عند الإرسال:
TypeScript
delete pub.privateNote;
والسيرفر يفحص:
TypeScript
body["publicNote"]
بينما publicNote لا يُرسل أصلاً.
النتيجة:
المستخدم يعتقد أن الملاحظة ستظهر، لكنها لا تظهر. والـ admin يرى publicWarning كأنه public note، وهو نص عام فقط.
الإصلاح: إما تغيّر الاسم إلى:
Private local note — saved only in your proof package
أو تضيف حقل حقيقي اسمه publicNote في:
OpenAPI
Zod
DB schema
admin review
public record
مع مراجعة قبل النشر.
3. أسماء metadata غير متطابقة بين frontend و API
الواجهة ترسل مثلاً:
TypeScript
wordCount
gpsMetadata
exifMetadata
لكن الـ OpenAPI/Zod يتوقع:
TypeScript
textWordCount
gpsMetadataDetected
exifMetadataDetected
النتيجة:
Zod غالباً سيحذف الحقول غير المعروفة، يعني معلومات مهمة لا تُخزّن كما تتوقع.
الإصلاح: وحّد الاسماء. الأفضل استخدام أسماء الـ API:
TypeScript
textWordCount
gpsMetadataDetected
exifMetadataDetected
4. مستوى الجودة يمكن التلاعب به من العميل
السيرفر يحسب الجودة:
TypeScript
const qualityLevel = computeQualityLevel(body);
لكن عند التخزين يستخدم:
TypeScript
qualityLevel: body.qualityLevel ?? qualityLevel
المشكلة:
أي شخص يستطيع إرسال qualityLevel: "A" من الطلب مباشرة.
الإصلاح: لا تقبل الجودة من العميل أبداً:
TypeScript
qualityLevel,
وخلي السيرفر وحده يقرر.
5. Admin password ضعيف كنظام إدارة
حالياً الـ admin password يُرسل في header:
TypeScript
x-admin-password
ويُخزن في:
TypeScript
sessionStorage
هذا مقبول كـ MVP، لكنه ليس جيداً لمشروع حساس.
الإصلاح المقترح:
لا تخزن كلمة السر في sessionStorage.
استخدم login endpoint يولّد session cookie:
HttpOnly
Secure
SameSite=Strict
استخدم crypto.timingSafeEqual للمقارنة.
أضف rate limit لمحاولات الدخول.
6. مشكلة خصوصية IP
في الوثائق تقول إن IP لا يرتبط بالسجل، لكن في الكود يوجد:
TypeScript
submitterIp: getIpHash(ip)
داخل جدول witness_records.
حتى لو كان hash، هو مرتبط بالسجل. وأيضاً الـ salt ثابت:
TypeScript
"silent-witness-salt"
الإصلاح: الأفضل:
لا تخزن IP hash داخل witness_records.
استخدم جدول rate limit منفصل.
استخدم HMAC بسِر من env:
TypeScript
crypto.createHmac("sha256", process.env.IP_HASH_SECRET!)
مقترحات تحسين مهمة
قبل النشر
أصلح خلل manifest/retraction token.
حدد: هل Public Note عام فعلاً أم خاص؟
وحّد أسماء safeDescriptor.
اجعل الجودة تُحسب من السيرفر فقط.
أضف migration/seed واضح للـ DB.
أزل كلام “demo records seeded” من replit.md أو أضف seed script فعلي.
تحسينات أمنية
اجعل cors() محدوداً بدل فتحه لكل المواقع.
اجعل rate limit في PostgreSQL أو Redis، وليس Map داخل الذاكرة.
لا تعتمد على in-memory rate limit مع Replit Autoscale.
أضف helmet.
أضف logging للأخطاء بدون كشف بيانات حساسة.
أضف endpoint منفصل:
/api/public/records/:hash يرجع فقط السجلات المنشورة.
/api/records/:hash للاستعمال الداخلي أو مع token.
تحسينات المنتج
1. صفحة “ماذا يثبت هذا؟” بلغة أبسط
لأن المشروع موجه لشهود وصحفيين، لازم تكون الجملة الأساسية واضحة جداً:
هذا لا يثبت أن الحادثة حصلت.
هذا يثبت فقط أن بصمة الملف كانت موجودة على السيرفر قبل وقت معيّن.
2. زر “اختبار الملف لاحقاً”
في صفحة السجل، أضف زر:
Verify a file against this record
يفتح /verify ومعه hash جاهز.
3. proof package أقوى
بدل ملف واحد، نزّل package يحتوي:
Plain text
manifest-public.json
retraction-token.txt
instructions.txt
هذا يقلل الخطأ ويحمي المستخدم.
4. وضع “صحفي / شاهد عادي”
الشاهد غير المتعلم يحتاج واجهة أبسط:
زر 1: اختر الملف
زر 2: احفظ الإثبات
زر 3: أرسل البصمة للسجل
وباقي التفاصيل تكون تحت “Advanced”.
حكمي النهائي
المشروع واعد جداً ومبني بطريقة أفضل من مجرد MVP عادي.
لكن حالياً عنده 3 مشاكل تمنعني من اعتباره جاهزاً تماماً:
خلل تحقق manifest.
التباس public/private note.
قبول qualityLevel من العميل.
بعد إصلاحهم، يصير مناسب للنشر التجريبي العام.
أما إذا بدك تستخدمه فعلياً مع صحفيين أو شهود بمناطق خطرة، لازم نعمل له hardening أمني كامل قبل الاعتماد عليه.
